# Odoo 20 Enterprise Accounting parity matrix

Generated by comparing the read-only Enterprise snapshot (`work/enterprise_account_menu_tree.json`) with a live Odoo ORM registry export from local database `odoo20` (`work/local_account_menu_actions_live_20261027.json`), using `work/export_local_accounting_snapshot.py` and `work/compare_accounting_parity_snapshots.py`. The local snapshot was captured on 2026-10-27 as Odoo superuser uid 1 and includes active Accounting menu routes, action metadata, resolved view field names, current model fields, and group membership. Scope: every Enterprise menu with an action (77 destinations). Matching model/view sequence is structural parity only; it does not prove identical rendering or workflow. A live authenticated Enterprise browser session exposed Balance Sheet, Profit and Loss, Cash Flow Statement, Trial Balance, and General Ledger screens. This route export predates the latest local interactive General Ledger and Trial Balance actions; their current mappings are covered by Odoo runtime tests. The broader destination-by-destination rendered audit remains open.

## Rendered Balance Sheet comparison

The supplied authenticated Enterprise screenshot (`/odoo/balance-sheet`) shows a centered report canvas with gray section bars, fine row separators, right-aligned account labels, amount and info columns, and a toolbar for as-of date, comparison, posted/accrual basis, currency, settings, and print. The visible balances are zero and intentionally low-contrast in this sample; this is a data state, not the report layout. The live screen also showed an unposted-entry warning, expandable groups, clickable amounts, and per-line information icons. The local interactive client action provides an as-of date, posted/all-entry filter, comparison modes, percentage/difference display, fold/unfold controls, grouped lines, amount drill-down, unposted-item warning, and PDF/XLSX actions. Currency selection, cash/accrual basis, and report-specific settings remain unavailable, the information tooltip is generic, and the local rendered screen is not verified against the authenticated Enterprise database.

The Statement Reports menu labels and ordering were verified against the Enterprise snapshot and the installed local registry. Profit and Loss, Balance Sheet, and Cash Flow Statement appear in the same order, followed by Depreciation Schedule. A runtime test checks the resolved route, labels, and ordering. The first three now open a shared FlousFlow OWL report viewer instead of the prior form-only wizard; their client-action type now matches the Enterprise route type.

Loans Analysis was compared against the Enterprise action and field metadata. The local action now resolves `pivot,list,form`, defaults only to Current (`draft`/`running`), has no forced grouping, and mirrors Enterprise's yearly pivot axes, principal/interest/payment measures, and visible measure labels. The search view adds loan-date and asset-group search/grouping; the local loan model has an optional asset-group classification because it has no native link to the asset engine. Its schedule list exposes equivalent principal/interest/payment plus calculated long/short-term balances. Loan records now show mapped amount, date, end date, expense account, outstanding balance, and status fields where the local model has equivalents. The computed end date equals the last generated installment date. The long/short account fields and Enterprise theoretical-balance formula remain different or unverified. A focused Odoo test verifies action order/context, mapped labels, schedule dates, views, and calculated balances.

Working Files now defaults to To Do (draft/in-review) and Paused records, matching Enterprise's selected filters. A Paused state stores the previous draft or in-review stage, and Resume restores that stage. The local Kanban is the initial view and list/form remain available as additional Community views. Enterprise still uses `account.return` with audit-cycle, tax-return, check, and filing fields, while Community uses a separate evidence/reviewer/approval model. The focused Odoo class verifies default filters and that pausing/resuming preserves the workflow stage.

The Tax Returns destination remains a FlousFlow internal localization-grid review flow because Community has no `account.return` model or Enterprise server action. The local record now tracks an editable filing deadline, workflow-generated review-submission date, and the actual company tax-lock date, and blocks direct writes to the latter audit dates. Its search/list/kanban expose deadline and submission data. Enterprise's `date_submission` may represent submission to a tax authority, while the local field records handoff to an internal reviewer; the field meaning and return-type-driven deadline logic are not identical. This adds operational traceability without claiming statutory filing parity.

Annual Report now opens a persistent Kanban/list workspace with a form, period/company/responsible metadata, an HTML content template, status workflow, chatter and PDF output. Its **Generate Financial Statements** button opens the existing annual financial wizard using the saved company's period and previous-year comparison; a separate Reporting > Statement Reports menu preserves direct access to that wizard. This maps Enterprise `audit.report` title/status/date/company/responsible/template fields and list destination. The model is not `audit.report`, and Community has no Knowledge article editor, nested report-page system, or Enterprise template lifecycle, so custom HTML content remains a reduced template equivalent.

Reconcile preserves the Enterprise open-item domain and account/partner grouping. Its Community action activates the standard posted and unreconciled filters with `journal_type=general`; Enterprise's `posted_lines` default maps to Community's `posted` filter. The Enterprise-only `auto_statement_processing` flag has no Community implementation and is not treated as equivalent. A focused Odoo test verifies the resolved local context.

The Assets action now resolves to `list,kanban,activity,form`, matching the Enterprise action's resolved view sequence. Community kanban and activity views render FlousFlow asset data; the action remains scoped to `recognition_type = asset`. The regression test and full Odoo suite passed after these views were added.

Depreciation Models now has the matching Configuration > Accounting menu route and `list,kanban,form` sequence. It reuses FlousFlow asset categories filtered to fixed-asset recognition, exposing the configured depreciation method, interval, accounts, and company. This is a functional mapping: the underlying `flousflow.account.asset.category` model does not reproduce Enterprise `account.depreciation.model` fields or behavior exactly.

### Community report engine verification

The Odoo 20 Community source includes `account.report` definitions, report lines/expressions/columns, composite sections, and generic tax-report data (`addons/account/models/account_report.py` and `addons/account/data/account_reports_data.xml`), but it does not ship the Enterprise `account_report` client-action renderer. FlousFlow now provides its own original OWL viewer for Profit and Loss, Balance Sheet, Cash Flow Statement, Trial Balance, and General Ledger, backed by the existing report engine; it does not use the Enterprise tag or code. The viewer supports date selection, posted/all entries, previous-period/year comparison, folding, account-move drill-down, draft-entry warning, and PDF/XLSX export. Trial Balance adds opening, debit, credit, and closing columns, period controls, totals, and amount-specific drill-down date scopes. General Ledger adds searchable account groups, dated entry rows, partner and currency labels, debit/credit, running balances, and entry-level drill-down. The Enterprise currency/basis/settings options and full visual rendering parity remain outstanding. Odoo 20 server-side report tests and static asset compilation do not establish local browser-rendered parity; the local Odoo 20 viewer still needs to be opened and visually compared in an authenticated browser.

## Remaining functional and view differences

- Purchase/sales accrual routes use Community order-line models, corresponding native domains/search views, and Odoo’s native accrued-order posting wizard. The two sales accrual lists now expose the same 13 fields as the Enterprise snapshot, including `unit_cost` and `total_cost`, mapped to Community `sale_margin`'s `purchase_price` and `_get_product_qty()` basis. The Enterprise snapshot does not expose its cost compute implementation, so exact formula identity is unverified. Enterprise `accrual_list_view` JavaScript behavior remains edition-specific.
- `account.move.line` now exposes `invoice_origin` through its parent move, `move_attachment_ids` through the move attachments, and `asset_ids` through the linked FlousFlow source-bill line. These close three field-name gaps using Community relations, but `asset_ids` points to `flousflow.account.asset` with a one-to-many link rather than Enterprise's `account.asset` many-to-many field.
- Analytic Report enables Community pivot/list/kanban/form/graph views; Enterprise also provides `grid`, unavailable in the checked Community source. Analytic Items has the same limitation.
- Working Files retains the FlousFlow evidence/review model, defaults to To Do and Paused records, and restores the saved stage when a file resumes. Enterprise audit cycles, return types, tax-unit links, and filing/check fields are still not equivalent. Annual Report now uses a persistent Kanban/list workspace and mapped title/status/date/company/responsible/template fields with PDF output; Enterprise's Knowledge article editor, nested page authoring, and template lifecycle remain unavailable in Community.
- Assets and loans use FlousFlow models because the Enterprise asset/loan models are not in local Community source. The Assets destination now exposes the same list/kanban/activity/form sequence as Enterprise; its kanban shows asset model, vendor, cost, residual value, and status. Loan records also expose the Enterprise list/form/kanban/pivot/graph sequence. Loan Analysis opens schedule rows in pivot/list/form order; its Current filter defaults to draft/running loans and groups by loan. Local loan lines expose related `loan_name` and `loan_state` for equivalent search/filter behavior, while retaining FlousFlow fields for opening/closing balance and posted moves. The underlying models and accounting workflows remain different.
- Financial Budgets remains on the FlousFlow budget model; Enterprise `account.report.budget` and its action are not in Community source. The menu is manager-only and regular accounting users have read-only ACLs, matching the Enterprise menu group's manager scope while retaining the richer FlousFlow budget workflow.
- Enterprise tax units, horizontal groups, checks, fiscal categories, return types, and online synchronization have no direct Community counterpart in the inspected source. The Depreciation Models route maps to FlousFlow asset categories, but its technical model and fields differ. The Fiscal Report menu now routes to FlousFlow Tax Report; country-specific statutory filing remains localization-dependent. Community Accounting Reports now has a manager-controlled list/form editor for report definitions, options, sections, lines, calculation expressions, and columns over the standard `account.report` model; Enterprise dynamic rendering and interactive report controls remain unavailable. Country-specific filing remains localization-dependent.
- Invoice Reminders now uses the matching menu route and list/kanban/form destination over FlousFlow reminder levels. The lifecycle and available actions are similar, but the underlying model and fields differ from Enterprise `account_followup.followup.line`; Enterprise reminder computation and mail activities are not proven equivalent.
- Enterprise financial reports use dynamic `account_report` client actions with interactive options and exports. FlousFlow report forms provide related output but are not screen-level matches; Community's `account.report` data model is present, but its Enterprise renderer is not.
